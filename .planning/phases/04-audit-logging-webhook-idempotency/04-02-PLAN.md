Add an idempotency check to the Calendly webhook POST handler. The guard must be placed AFTER signature verification and event type filtering, but BEFORE any business logic (user lookup, allowlist check, cancellation).

Import `Prisma` from `@prisma/client` at the top of the file:
```typescript
import { Prisma } from '@prisma/client'
```

After the `if (payload.event !== 'invitee.created')` check (around line 85), extract the invitee URI and add the idempotency guard:

```typescript
// Idempotency check — use invitee URI as the dedup key (unique per invitee, not per event)
const inviteeUri = payload.payload.uri
try {
  await prisma.processedWebhookEvent.create({
    data: {
      idempotencyKey: inviteeUri,
      source: 'CALENDLY',
      eventType: payload.event,
    },
  })
} catch (error) {
  if (
    error instanceof Prisma.PrismaClientKnownRequestError &&
    error.code === 'P2002'
  ) {
    console.log('[Calendly Webhook] Duplicate event detected, skipping:', inviteeUri)
    return NextResponse.json({ received: true, duplicate: true })
  }
  throw error
}
```

Key details:
- Use `payload.payload.uri` (the invitee URI, e.g., `https://api.calendly.com/scheduled_events/EVT001/invitees/INV001`) — NOT the scheduled_event URI which is shared across invitees in group events.
- The `source: 'CALENDLY'` field is for querying/debugging only; the unique constraint is on `idempotencyKey` alone.
- On P2002 (unique constraint violation), return 200 with `{ received: true, duplicate: true }` — this tells Calendly the webhook was received (stops retries) while indicating it was a duplicate.
- The `throw error` re-throws any unexpected database error (not a duplicate).
- Use `instanceof Prisma.PrismaClientKnownRequestError` for type-safe error handling (not bare `error.code`).

The existing destructuring of `payload.payload` fields (line 87) should remain — the `uri` is now also used for idempotency above it. This is fine; `inviteeUri` is a separate const used only for the dedup key.
