<feature>
  <name>AES-256-GCM encryption primitive</name>
  <files>src/lib/encryption.ts, src/lib/encryption.test.ts</files>
  <behavior>
    encrypt(plaintext: string) → string
    - Returns a string in format: `enc:v1:{ivHex}:{authTagHex}:{ciphertextHex}`
    - IV is 12 random bytes (96-bit, required for GCM) generated fresh per call via crypto.randomBytes(12)
    - Auth tag is 16 bytes (128-bit GCM default)
    - Each call with the same input produces a different output (random IV)

    decrypt(envelope: string) → string
    - Parses the enc:v1: prefix and splits on ':'
    - Reconstructs IV, authTag, ciphertext from hex segments
    - Calls createDecipheriv('aes-256-gcm', KEY, iv), sets auth tag, decrypts
    - Returns the original plaintext as UTF-8 string
    - Throws Error('Invalid encryption envelope format or unsupported version') if prefix is not 'enc:v1:'
    - Throws if GCM auth tag validation fails (tampered ciphertext or wrong key)

    Cases:
    - encrypt('test-token') → string starting with 'enc:v1:'
    - decrypt(encrypt('test-token')) === 'test-token'
    - encrypt('x') !== encrypt('x') (different ciphertext each call)
    - decrypt(tampered_envelope) → throws
    - decrypt('not-valid') → throws 'Invalid encryption envelope format'

    The module reads ENCRYPTION_KEY from env.ENCRYPTION_KEY (imported from '@/env'), NOT from process.env directly. This ensures the key was validated at startup.
  </behavior>
  <implementation>
    After tests are RED:

    Create src/lib/encryption.ts:
    - `import crypto from 'crypto'` (Node.js built-in — no install needed)
    - `import { env } from '@/env'`
    - `const ALGORITHM = 'aes-256-gcm'`
    - `const KEY = Buffer.from(env.ENCRYPTION_KEY, 'hex')` — read once at module load time; 32 bytes
    - `export function encrypt(plaintext: string): string` — generates 12-byte IV via crypto.randomBytes(12), uses createCipheriv, calls cipher.final() then cipher.getAuthTag(), returns version-prefixed envelope
    - `export function decrypt(envelope: string): string` — validates prefix, splits on ':', reconstructs buffers, uses createDecipheriv, calls decipher.setAuthTag(), returns decrypted UTF-8

    Critical constraints:
    - Do NOT import from prisma.ts, session.ts, or any other src/lib/*.ts file — circular dependency risk
    - Do NOT import from src/lib/encryption.ts inside env.ts — env.ts must remain a leaf module

    - IV MUST be randomly generated per call — never reuse with AES-GCM
    - Use 'aes-256-gcm' (authenticated) not 'aes-256-cbc' (unauthenticated)

  <action>
    Create src/lib/encryption.ts with the minimal implementation to pass all 4 tests:

    ```typescript
    import crypto from 'crypto'
    import { env } from '@/env'

    const ALGORITHM = 'aes-256-gcm'

    // Read key once at module load time — env validation already confirmed it exists and is 64 hex chars
    const KEY = Buffer.from(env.ENCRYPTION_KEY, 'hex') // 32 bytes

    export function encrypt(plaintext: string): string {
      const iv = crypto.randomBytes(12) // 96-bit IV required for GCM
      const cipher = crypto.createCipheriv(ALGORITHM, KEY, iv)
      const ciphertext = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()])
      const authTag = cipher.getAuthTag() // 128-bit authentication tag
      // Version-prefixed format enables future key rotation
      return `enc:v1:${iv.toString('hex')}:${authTag.toString('hex')}:${ciphertext.toString('hex')}`
    }

    export function decrypt(envelope: string): string {
      if (!envelope.startsWith('enc:v1:')) {
        throw new Error('Invalid encryption envelope format or unsupported version')
      }
      const [, , ivHex, authTagHex, ciphertextHex] = envelope.split(':')
      const iv = Buffer.from(ivHex, 'hex')
      const authTag = Buffer.from(authTagHex, 'hex')
      const ciphertext = Buffer.from(ciphertextHex, 'hex')
      const decipher = crypto.createDecipheriv(ALGORITHM, KEY, iv)
      decipher.setAuthTag(authTag)
      return Buffer.concat([decipher.update(ciphertext), decipher.final()]).toString('utf8')
    }
    ```
