<task type="auto">
  <name>Task 2: Create src/env.ts with full Zod-validated env schema</name>
  <files>src/env.ts</files>
  <action>
    Create a new file src/env.ts (NOT src/lib/env.ts — must be at src/ root per T3 convention to avoid import ambiguity).

    The file must:
    - Import `createEnv` from `@t3-oss/env-nextjs`
    - Import `z` from `zod`
    - Call `createEnv()` with a `server` block, a `client` block, and an explicit `runtimeEnv` block
    - Export the result as `env`

    Server schema (all required unless noted):
    - `DATABASE_URL: z.string().url()` — Prisma reads DATABASE_URL directly, but include in schema for consistency and startup validation
    - `SESSION_SECRET: z.string().min(32, 'SESSION_SECRET must be at least 32 characters')` — NO .default(), NO .optional(). This enforces ENV-02.
    - `ENCRYPTION_KEY: z.string().length(64).regex(/^[0-9a-f]+$/, 'ENCRYPTION_KEY must be 64 hex characters (32 bytes)')` — NO .default(), NO .optional().
    - `CALENDLY_CLIENT_ID: z.string().min(1)`
    - `CALENDLY_CLIENT_SECRET: z.string().min(1)`
    - `CALENDLY_REDIRECT_URI: z.string().url()`
    - `CALENDLY_WEBHOOK_SIGNING_KEY: z.string().min(1)` — NO .default(), NO .optional(). Making this required closes the conditional bypass security gap.
    - `STRIPE_SECRET_KEY: z.string().startsWith('sk_')`
    - `STRIPE_WEBHOOK_SECRET: z.string().startsWith('whsec_')`
    - `STRIPE_PRICE_PRO_MONTHLY: z.string().startsWith('price_')`
    - `STRIPE_PRICE_PRO_YEARLY: z.string().startsWith('price_')`
    - `STRIPE_PRICE_BUSINESS_MONTHLY: z.string().startsWith('price_')`
    - `STRIPE_PRICE_BUSINESS_YEARLY: z.string().startsWith('price_')`
    - `NODE_ENV: z.enum(['development', 'test', 'production']).default('development')` — the only key with a default; safe for NODE_ENV.

    Client schema:
    - `NEXT_PUBLIC_APP_URL: z.string().url().optional()`

    runtimeEnv: Map every server and client key explicitly to process.env. Every key in server/client MUST appear in runtimeEnv or validation sees undefined and fails with a confusing error.

    Critical constraints:
    - src/env.ts must NOT import from any src/lib/*.ts file — it is a leaf module. Only imports: @t3-oss/env-nextjs and zod.
    - The `runtimeEnv` mapping is required by @t3-oss/env-nextjs and cannot be omitted — the library cannot auto-read process.env due to Next.js static analysis.
    - Do NOT add skipValidation — validation must always run.

    Use the exact pattern from the research file's Pattern 1 section as a reference.
  </action>
  <verify>
    - `npx tsc --noEmit` passes with no errors related to src/env.ts
    - With all required vars in .env.local: `node -e "require('./src/env.ts')"` succeeds (may need ts-node — alternatively verify via next build step in plan 03)
    - File exists at src/env.ts (not src/lib/env.ts)
    - `grep -c "createEnv" src/env.ts` returns 1
    - `grep -c "runtimeEnv" src/env.ts` returns 1
    - `grep "SESSION_SECRET" src/env.ts | grep -c "min(32)"` returns 1
    - `grep "ENCRYPTION_KEY" src/env.ts | grep -c "length(64)"` returns 1
    - `grep "CALENDLY_WEBHOOK_SIGNING_KEY" src/env.ts | grep -cv "optional\|default"` is 1 (not optional, no default)
  </verify>
  <done>src/env.ts exports a fully typed env object; all 14 server vars are declared; SESSION_SECRET, ENCRYPTION_KEY, and CALENDLY_WEBHOOK_SIGNING_KEY are required with no defaults or optionals; runtimeEnv maps all keys; TypeScript compiles cleanly</done>
