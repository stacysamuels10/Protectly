  <name>Task 1: Migrate calendly.ts from axios to native fetch</name>
  <files>src/lib/calendly.ts</files>
  <action>
    Replace `import axios from "axios"` with no import (native fetch is global). Migrate all 7 call sites following these rules:

    **Critical: Error shape preservation.** The 401-retry logic in `calendlyRequest` (line 318) checks `error.response?.status === 401`. All fetch calls that detect non-2xx responses must throw an error with the same `.response.status` shape. Use inline error augmentation (not a separate class -- YAGNI for 7 call sites):

    ```typescript
    if (!response.ok) {
      const error: any = new Error(`HTTP ${response.status}`);
      error.response = { status: response.status };
      throw error;
    }
    ```

    **Critical: Add `cache: 'no-store'` to all fetch calls** since these are OAuth/mutation operations that must never be cached by Next.js fetch extensions.

    **Migration for each call site:**

    1. `exchangeCodeForTokens()` (line 132): `axios.post` → `fetch` with `method: "POST"`, `headers: { "Content-Type": "application/json" }`, `body: JSON.stringify({...})`, `cache: 'no-store'`. Parse response with `await response.json()`. Return the parsed JSON with the same type assertion.

    2. `refreshAccessToken()` (line 152): Same pattern as #1. `axios.post` → `fetch POST` with JSON body.

    3. `getCalendlyUser()` (line 172): `axios.get` → `fetch` (GET is default method). Keep the Authorization header. Parse `await response.json()` and return `data.resource`.

    4. `getEventTypes()` (line 185): `axios.get` with params → `fetch` with URL params. Convert the `params: { user: userUri, active: true }` to a URLSearchParams query string appended to the URL: `` `${CALENDLY_API_BASE_URL}/event_types?${new URLSearchParams({ user: userUri, active: 'true' })}` ``. Parse `await response.json()` and return `data.collection`.

    5. `createWebhookSubscription()` (line 204): `axios.post` with body and headers → `fetch POST` with JSON body, Authorization + Content-Type headers. Parse response and return `data.resource`.

    6. `deleteWebhookSubscription()` (line 240): `axios.delete` → `fetch` with `method: "DELETE"`. No response body needed.

    7. `cancelCalendlyEvent()` (line 259): `axios.post` with body and headers → `fetch POST` with JSON body. Keep the existing try/catch error logging. For the catch block, update the error logging to handle the new error shape (the `.response?.status` and `.response?.data` references still work since we set `error.response = { status }` on throw). The `response.data` on successful cancel becomes `await response.json()`. Keep the `console.log` for response status.

    **Do NOT create an HttpError class or fetch wrapper function.** The research explicitly recommends against this for only 7 call sites.
  </action>

    **Part A: Update calendly.test.ts**

    Three tests spy on `axiosMock.default.post` to intercept the `refreshAccessToken` call during 401 recovery. After migrating calendly.ts to native fetch, these tests must mock `globalThis.fetch` instead of `axios.post`.

    For the 3 affected tests ("uses decrypted refresh token on 401", "propagates error gracefully when refreshAccessToken throws", "retry after 401 refresh uses the NEW access token"):

    1. Remove the `import('axios')` and `vi.spyOn(axiosMock.default, 'post')` pattern.
    2. Replace with `vi.spyOn(globalThis, 'fetch')` that intercepts the OAuth token refresh call to `https://auth.calendly.com/oauth/token`.
    3. The mock must return a Response-like object: `{ ok: true, json: async () => ({ access_token: ..., refresh_token: ..., ... }) }` for success cases.
    4. For the "propagates error gracefully" test, mock fetch to reject with an error (or return `{ ok: false, status: 401 }` -- but since refreshAccessToken throws on !response.ok, the test should see that error propagated).

    **Important mock consideration:** The `calendlyRequest` function calls `requestFn(accessToken)` first, and on 401 calls `refreshAccessToken(refreshToken)` which now uses `fetch`. The `requestFn` is already a `vi.fn()` mock. Only the `refreshAccessToken` path needs the `globalThis.fetch` mock.

    However, since `refreshAccessToken` now uses `globalThis.fetch`, and `requestFn` is a separate mock function (not fetch), the `globalThis.fetch` spy only needs to handle the refresh token POST call. Use `mockImplementation` or `mockResolvedValue` to return the expected token response.

    Remove the `axiosPostSpy.mockRestore()` cleanup calls and replace with `fetchSpy.mockRestore()` or use `beforeEach`/`afterEach` for cleanup.

    The test for "propagates a user-friendly error when decrypt throws" does NOT mock axios and needs no changes.

    **Part B: Remove packages**

    Run `npm uninstall axios` and `npm uninstall node-fetch` to remove both packages from package.json AND update package-lock.json atomically.

    Do NOT manually edit package.json — use `npm uninstall` which handles both files.

    **Part C: Verify no axios references remain**
