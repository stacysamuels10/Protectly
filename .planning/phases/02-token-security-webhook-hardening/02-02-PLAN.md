<objective>
Add decrypt() calls to both token-reading code paths (calendlyRequest in src/lib/calendly.ts and cancelBookingWithRetry in src/app/api/webhooks/calendly/route.ts) via TDD. Both functions also contain a 401-triggered token refresh that writes new tokens back — these writes must use encrypt().

Purpose: Closes TOK-03. After Plan 01 encrypted the write path and Plan 03 will migrate existing rows, this plan ensures all read paths can consume the enc:v1: envelope format. The TDD approach is used because both functions have well-defined I/O contracts (encrypted input → decrypted output passed to API call) and a subtle pitfall: the refresh sub-path must also encrypt before writing.

Output: Both token-reading functions wrap reads with decrypt() and wrap refresh writes with encrypt(); test coverage proves both the happy path and the refresh path.
</objective>

    - On 401: refreshAccessToken is called with decrypt(user.calendlyRefreshToken) (the decrypted refresh token)

    - On decrypt() throw (corrupted envelope): a user-friendly error propagates, not a raw crypto error

    cancelBookingWithRetry() behavior:

    4. cancelBookingWithRetry: 401 triggers refresh with decrypted token; refresh writes encrypt new tokens to DB
