  <name>Task 3: Replace non-constant-time email comparison with timing-safe SHA-256 check</name>
  <files>src/app/api/webhooks/calendly/route.ts</files>
  <action>
    Open `src/app/api/webhooks/calendly/route.ts`. The current email comparison is a Set.has() call (around line 139):
    ```typescript
    const isEmailApproved = (email: string) => allowedEmails.has(email.toLowerCase())
    ```

    Make the following changes:

    1. Add `import crypto from 'node:crypto'` to the imports if not already present. (Phase 1 Plan 03 may have added it — check first with grep; if present, skip.)

    2. Locate where `allowedEmails` is built. It is a Set constructed from `globalAllowlist.entries`. Replace the construction of `allowedEmails` (a Set of plaintext emails) with a Set of SHA-256 hex hashes:
    ```typescript
    // Replace the old Set construction:
    // const allowedEmails = new Set(...)
    // With:
    const allowedEmailHashes = new Set(
      (globalAllowlist?.entries || []).map(e =>
        crypto.createHash('sha256').update(e.email.toLowerCase()).digest('hex')
      )
    )
    ```
    If `allowedEmails` is used elsewhere in the route (for non-comparison purposes, like building a list for logging), keep a separate plaintext Set for those uses and rename the hash Set clearly.

    3. Replace the `isEmailApproved` function with:
    ```typescript
    function isEmailApproved(email: string): boolean {
      const candidateHashHex = crypto.createHash('sha256').update(email.toLowerCase()).digest('hex')
      const candidateHash = Buffer.from(candidateHashHex, 'hex')
      for (const storedHashHex of allowedEmailHashes) {
        const storedHash = Buffer.from(storedHashHex, 'hex')
        try {
          if (crypto.timingSafeEqual(candidateHash, storedHash)) return true
        } catch {
          // Lengths should always match (both SHA-256 = 32 bytes) but handle defensively
        }
      }
      return false
    }
    ```

    Make it a named function declaration (not an arrow function const) so it can be called before its declaration if needed. If the existing code uses it as a const arrow function, convert to a `function` declaration.

    4. Verify that all call sites of `isEmailApproved` remain unchanged — only the implementation changes, not the call signature.

    DO NOT change any other logic in the route — only the allowedEmails Set construction and isEmailApproved implementation.
  </action>
