<task type="auto">
  <name>Task 2: Add optional Upstash env vars to env.ts</name>
  <files>src/env.ts</files>
  <action>
    Open `src/env.ts`. In the `server` section of `createEnv()`, add two optional fields for Upstash credentials. Place them after the existing Stripe price ID entries and before `NODE_ENV`:

    ```typescript
    // Upstash Redis — optional; when absent, rate limiting degrades gracefully (all checks pass)
    UPSTASH_REDIS_REST_URL: z.string().url().optional(),
    UPSTASH_REDIS_REST_TOKEN: z.string().min(1).optional(),
    ```

    In the `runtimeEnv` object, add the corresponding process.env mappings after the existing Stripe entries:

    ```typescript
    UPSTASH_REDIS_REST_URL: process.env.UPSTASH_REDIS_REST_URL,
    UPSTASH_REDIS_REST_TOKEN: process.env.UPSTASH_REDIS_REST_TOKEN,
    ```

    IMPORTANT: These must be `.optional()` — NOT required. Removing `.optional()` would break local development and all test environments where Upstash is not configured. The middleware reads `process.env.UPSTASH_REDIS_REST_URL` directly (bypassing env.ts validation) for exactly this reason, but the vars must still be declared in env.ts for completeness and future typed access.

    Do NOT add NEXT_PUBLIC_ prefixed versions — these are server-side secrets.
    Do NOT add validation beyond `.url().optional()` for the URL and `.min(1).optional()` for the token.
  </action>
  <verify>
    - `grep -n "UPSTASH_REDIS_REST_URL" src/env.ts` returns at least 2 lines (one in server schema, one in runtimeEnv)
    - `grep -n "UPSTASH_REDIS_REST_TOKEN" src/env.ts` returns at least 2 lines
    - `grep "UPSTASH_REDIS_REST_URL" src/env.ts` shows `.optional()` on the schema line
    - `npx tsc --noEmit 2>&1 | grep env.ts` — no TypeScript errors in env.ts
    - `npx vitest run 2>&1 | tail -5` — existing test suite still passes (env vars are optional so no startup failure)
  </verify>
  <done>env.ts declares both Upstash vars as optional; TypeScript compiles; existing tests pass; app starts without Upstash credentials set</done>
</task>
