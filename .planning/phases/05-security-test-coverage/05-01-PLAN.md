**Part A: Extract guest check mode pure function**

Create `src/lib/guest-check.ts` with the following:

1. Export an interface `GuestCheckResult` with three fields: `isApproved: boolean`, `rejectionReason: string`, `useGuestCancelMessage: boolean`.

2. Export a function `evaluateGuestCheckMode(mode: string, inviteeApproved: boolean, approvedGuests: string[], unapprovedGuests: string[], guestEmails: string[])` that returns `GuestCheckResult`.

3. The function body is the `switch (user.guestCheckMode)` block from `src/app/api/webhooks/calendly/route.ts` lines 189-241, adapted as follows:
   - ALLOW_ALL: returns `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - STRICT: if `!inviteeApproved` returns rejected with 'Email not on allowlist'; if `unapprovedGuests.length > 0` returns rejected with `Unapproved guest(s): ${unapprovedGuests.join(', ')}` and `useGuestCancelMessage: true`; otherwise approved
   - PRIMARY_ONLY: `isApproved = inviteeApproved`, reason 'Email not on allowlist' when false
   - ANY_APPROVED: `isApproved = inviteeApproved || approvedGuests.length > 0`, reason 'No participants on allowlist' when false
   - NO_GUESTS: if `!inviteeApproved` rejected 'Email not on allowlist'; if `guestEmails.length > 0` rejected with `Additional guests not allowed: ${guestEmails.join(', ')}` and `useGuestCancelMessage: true`; otherwise approved
   - default: same as STRICT (fallback)

4. Update `src/app/api/webhooks/calendly/route.ts`:
   - Add `import { evaluateGuestCheckMode } from '@/lib/guest-check'` at top
   - Replace the switch block (lines 185-241) with a call to `evaluateGuestCheckMode(user.guestCheckMode, inviteeApproved, approvedGuests, unapprovedGuests, guestEmails)`
   - Use the returned `isApproved`, `rejectionReason`, and `useGuestCancelMessage` (if true, set `cancelMessage = user.guestCancelMessage`)
   - Preserve all surrounding code (logging, eventType lookup, booking creation, cancellation) exactly as-is

5. Run `npx vitest run` to confirm existing 52 tests still pass after the refactor.

**Part B: Create webhook signature validation tests**

Create `src/lib/webhook.test.ts` with at least 6 tests covering TST-01:

1. Import `crypto` from 'crypto' and import `verifyWebhookSignature, isTimestampValid` from './webhook'.

2. Create a helper function `makeValidSignature(payload: string, key: string, timestampSec?: number): string` that:
   - Uses `timestampSec ?? Math.floor(Date.now() / 1000)` for the timestamp
   - Builds `signedPayload = ${ts}.${payload}`
   - Computes HMAC-SHA256 with the key
   - Returns `t=${ts},v1=${sig}`

3. Tests for `verifyWebhookSignature`:
   - "accepts a valid signature": generate a valid signature with makeValidSignature, assert returns `true`
   - "rejects when key is wrong": sign with 'correct-key', verify with 'wrong-key', assert `false`
   - "rejects when signature header is null": pass `null` as signatureHeader, assert `false`
   - "rejects when payload is tampered": sign original payload, verify with different payload, assert `false`

4. Tests for `isTimestampValid` (use `vi.useFakeTimers()` and `vi.setSystemTime()` for ALL timestamp tests):
   - "accepts timestamp 59 seconds old": freeze time, create header `t=${frozen - 59},...`, assert `true`
   - "rejects timestamp 61 seconds old": freeze time, create header `t=${frozen - 61},...`, assert `false`
   - "rejects when signature header is null": assert `false`

5. Use `beforeEach(() => vi.useFakeTimers())` and `afterEach(() => vi.useRealTimers())` for the timestamp describe block.

Create `src/lib/guest-check.test.ts` testing the pure `evaluateGuestCheckMode` function with 15 test cases (5 modes x 3 scenarios).

1. Import `evaluateGuestCheckMode` from './guest-check'. No mocks needed — this is a pure function.

2. Structure: one `describe` block per mode.

3. For each mode, test 3 scenarios. Use these consistent test data patterns:
   - **Approved invitee scenario:** `inviteeApproved = true`, `approvedGuests = []`, `unapprovedGuests = []`, `guestEmails = []`
   - **Approved guests scenario:** `inviteeApproved = false`, `approvedGuests = ['guest1@example.com']`, `unapprovedGuests = ['guest2@example.com']`, `guestEmails = ['guest1@example.com', 'guest2@example.com']`
   - **Unapproved guests scenario:** `inviteeApproved = true`, `approvedGuests = []`, `unapprovedGuests = ['bad@example.com']`, `guestEmails = ['bad@example.com']`

4. Expected results per mode per scenario:

   **ALLOW_ALL:**
   - Approved invitee: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Approved guests mix: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Unapproved guests: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`

   **STRICT:**
   - Approved invitee (no guests): `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Unapproved invitee with mixed guests: `{ isApproved: false, rejectionReason: 'Email not on allowlist', useGuestCancelMessage: false }`
   - Approved invitee with unapproved guests: `{ isApproved: false, rejectionReason: 'Unapproved guest(s): bad@example.com', useGuestCancelMessage: true }`

   **PRIMARY_ONLY:**
   - Approved invitee: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Unapproved invitee: `{ isApproved: false, rejectionReason: 'Email not on allowlist', useGuestCancelMessage: false }`
   - Approved invitee + unapproved guests: `{ isApproved: true, ... }` (guests don't matter)

   **ANY_APPROVED:**
   - Approved invitee: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Unapproved invitee with one approved guest: `{ isApproved: true, ... }`
   - Unapproved invitee with no approved guests: `{ isApproved: false, rejectionReason: 'No participants on allowlist', useGuestCancelMessage: false }`

   **NO_GUESTS:**
   - Approved invitee, no guests: `{ isApproved: true, rejectionReason: '', useGuestCancelMessage: false }`
   - Unapproved invitee: `{ isApproved: false, rejectionReason: 'Email not on allowlist', useGuestCancelMessage: false }`
   - Approved invitee with guests: `{ isApproved: false, rejectionReason: contains 'Additional guests not allowed', useGuestCancelMessage: true }`

5. Use exact string matching for rejectionReason where specified. Use `toContain` or `toMatch` for messages containing dynamic content (guest email lists).
