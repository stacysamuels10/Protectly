## Interaction Contracts

Primary visual anchor: the filter toolbar pill tabs.

### Filter Toolbar (ACTV-01, ACTV-04)

Layout: Single row — pill tabs on the left, search input on the right. On screens < 640px, tabs wrap to a second row above the search input.

- **Pill tabs:** `Tabs` component with `TabsList` container. Tab values: `ALL`, `APPROVED`, `REJECTED`, `RATE_LIMITED`. Labels: "All", "Approved", "Rejected", "Rate Limited". Each tab shows a count badge inline: `All (42)`, `Approved (30)`, etc.
- **Count badge on tab:** Small inline `<span>` with `bg-muted text-muted-foreground rounded-full px-1.5 py-0.5 text-xs` — not the `Badge` component (which uses border/color). Count source: `statusCounts` from API response (always unfiltered totals).
- **Active tab state:** `data-[state=active]:bg-background data-[state=active]:shadow-sm` — white pill on muted background, matching RESEARCH.md tabs.tsx code.
- **Clicking a tab:** Updates URL param `?status=VALUE` (ALL removes the param), resets `?page` to 1. Uses `router.replace`.
- **Search input:** `Input` component, placeholder "Search by email…", Search icon (lucide `Search`, 16px) as left adornment inside input. Debounced 300ms. Updates URL param `?q=VALUE` (empty removes param), resets `?page` to 1. No submit button.

### Activity Table Rows

Each row (`div` with `flex items-center justify-between py-3 border-b last:border-0`):

- **Left column:** Status `Badge` (success/error/warning variant) + name/email block + rejection reason subtitle (REJECTED only)
  - Primary text: `inviteeEmail` — 16px weight 400
  - Secondary text: `inviteeName · eventType.name` — 14px `text-muted-foreground`
  - Rejection reason (REJECTED rows only): `"Reason: {rejectionReason}"` — 14px `text-muted-foreground` on a new line below secondary text. Always visible, no interaction needed.
- **Right column:** Timestamp string (`formatDateTime(attempt.createdAt)`) — 14px `text-muted-foreground`. On REJECTED rows, the "Add to allowlist" button appears here in place of (or beside) the timestamp.

Source: CONTEXT.md D-05, D-06; existing page.tsx row structure

### Add to Allowlist Button (XFEAT-01, XFEAT-02)

Appears only on REJECTED status rows. Composed of `DropdownMenu`:

- **Trigger:** `Button` variant="outline" size="sm" with `ChevronDown` icon (lucide, 14px). Label: "Add to allowlist" (idle state).
- **Dropdown items:**
  1. "Add email (user@example.com)" — POSTs to `/api/allowlists/{allowlistId}/entries` with body `{ emails: ["user@example.com"] }`
  2. "Add domain (@example.com)" — POSTs to `/api/allowlists/{allowlistId}/domains` with body `{ domains: ["@example.com"] }`
- **Loading state:** Button disabled, label "Adding…", no spinner (loading state is transient < 500ms typical).
- **Success state:** Button label changes to "Added" (disabled, variant="outline"). Row stays in place. Toast fires: title "Added to allowlist", description "user@example.com has been added." variant="success".
- **Error state:** Button returns to idle "Add to allowlist". Toast fires: title "Failed to add", description from `data.error` (e.g. "example.com is a free email provider"). variant="destructive".
- **Domain add blocked (free provider):** API returns 400. Client shows destructive toast with `data.error` — same error path as above.

Source: CONTEXT.md D-09, D-10, D-11, D-12; RESEARCH.md Pattern 4; add-domain-dialog.tsx toast pattern

### Pagination (ACTV-03)

Appears below the activity table. Only rendered when `total > 25`.

- **Control layout:** `"< 1 2 3 ... 10 >"` numbered pages. Previous (`<`) and Next (`>`) arrow buttons as `Button` variant="outline" size="sm". Current page highlighted with `bg-primary text-primary-foreground`. Ellipsis (`...`) shown when page count > 7.
- **Count line:** `"Showing {start}–{end} of {total}"` — 14px `text-muted-foreground`, centered below pagination controls.
- **Page size:** 25 items per page (fixed). No page size selector.
- **Clicking a page number:** Updates URL param `?page=N`. Uses `router.replace`.

Source: CONTEXT.md D-07, D-08

### Loading State (Claude's Discretion — resolved)

While the client is fetching (initial mount or after filter/search/page change):

- **Skeleton rows:** 5 skeleton rows replacing the activity list. Each skeleton row: gray rounded pill (14px tall) for the badge area, two gray rounded lines for name/email. Use Tailwind `animate-pulse bg-muted rounded` — no external skeleton library.
- **Stats cards:** Retain their last-fetched values during refetch (no skeleton on stats cards — avoids layout shift).
- **Filter toolbar:** Remains interactive (tabs + search stay enabled during load — optimistic UX).

Source: Claude's Discretion (RESEARCH.md); Tailwind animate-pulse pattern

### Empty States (Claude's Discretion — resolved)

Two distinct empty states:

1. **Overall empty (no activity ever):** Centered in card. Icon: `Activity` (lucide, 32px, `text-primary`), in 64px circle `bg-primary/10`. Heading: "No activity yet" (18px semibold). Body: "Booking attempts will appear here once your Calendly webhook is active and someone tries to schedule a meeting." Sub-body: "Each booking is automatically checked against your allowlist." — carries over from existing page.tsx empty state exactly.

2. **Filtered empty (filter/search returns no results):** Centered in card. Icon: `Search` (lucide, 32px, `text-muted-foreground`), in 64px circle `bg-muted`. Heading: "No results found" (18px semibold). Body: "No bookings match your current filter. Try a different status or clear your search." No CTA button (user adjusts filter directly in toolbar).

Source: existing page.tsx (empty state 1), Claude's Discretion (empty state 2)

## Accessibility Notes

- `TabsList` uses `role="tablist"` via Radix — keyboard arrow-key navigation between tabs is automatic.
- `TabsTrigger` uses `aria-selected` via Radix — screen readers announce active tab.
- Search `Input` must have `aria-label="Search activity by email"` (no visible label in single-row toolbar layout).
- "Add to allowlist" `DropdownMenu` uses Radix focus trap and keyboard nav automatically.
- Pagination buttons: previous/next must have `aria-label="Previous page"` / `aria-label="Next page"`. Current page button: `aria-current="page"`.
- Rejection reason subtitle is always-visible text (not tooltip) — screen readers read it inline with the row content.
