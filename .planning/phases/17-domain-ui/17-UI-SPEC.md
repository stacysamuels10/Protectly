## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline icon padding (`mr-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`) |
| md | 16px | Default element spacing (`gap-4`, `py-4`) |
| lg | 24px | Section padding (`space-y-6` gaps between page sections) |
| xl | 32px | Layout gaps between major cards |
| 2xl | 48px | Page-level empty state vertical padding (`py-12`) |
| 3xl | 64px | Not used in this phase |

Exceptions: Touch targets for icon-only buttons (DropdownMenuTrigger) rendered at 40px (`h-10 w-10`) to meet 44px minimum — use `size="icon"` Button variant which yields `h-9 w-9`; wrap in sufficient hit area.

Source: `allowlist-table.tsx` and `allowlist/page.tsx` spacing patterns observed.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` — `--background` (#ffffff) | Page background, dialog backgrounds, card surfaces |
| Secondary (30%) | `hsl(210 10% 96%)` — `--muted` (#f3f5f7) | Table row zebra tones, muted text areas, usage bar track |
| Accent (10%) | `hsl(0 3% 13%)` — `--primary` (#221f1f dark charcoal) | Primary CTA buttons, usage bar fill, icon tint, focus ring |
| Destructive | `hsl(0 84% 60%)` — `--destructive` (#ef4444) | Remove domain DropdownMenuItem text, destructive toast variant |

Accent reserved for: primary "Add Domain" button, usage bar fill (`bg-primary`), icon containers (`bg-primary/10` with `text-primary`), focus rings. Never used for informational badges or passive UI chrome.

Informational scope warning uses `bg-warning-light` (#FEF3C7) with `text-warning` (#F59E0B) — these are semantic status colors, not accent.

Domain type badge uses `variant="secondary"` on `<Badge>` — renders `bg-secondary text-secondary-foreground` (slate gray #857e90 background, white text).

Source: `src/app/globals.css` CSS variables, `tailwind.config.ts` status color extensions, `allowlist-table.tsx` and `allowlist/page.tsx` existing patterns.

## Interaction Contracts

### AddDomainDialog
- Trigger: `<Button>` with `Plus` icon, label "Add Domain", rendered in allowlist page header alongside existing CsvImportButton, CsvExportButton, AddEmailDialog buttons.
- Dialog opens on trigger click; controlled via `useState(false)`.
- Dialog body layout (top to bottom):
  1. `DialogHeader` — title + description
  2. Scope warning — `rounded-md bg-warning-light p-3 text-sm` with `AlertTriangle` icon and copy
  3. Input field — `type="text"`, placeholder `@company.com`, label "Domain *", required
  4. `DialogFooter` — Cancel (outline) + Add Domain (primary, disabled during load)
- On submit: `e.preventDefault()`, set loading=true, `fetch POST /api/allowlists/{id}/domains` with `{ domains: [domain.trim()] }`.
- Response routing:
  - `!response.ok` → throw with `data.error`, show destructive toast, keep dialog open
  - `data.added > 0` → show success toast, close dialog, clear input, call `router.refresh()`
  - `data.duplicates.length > 0` → show duplicate toast, keep dialog open
  - `data.invalid.length > 0` → show invalid format toast, keep dialog open
- Input clears only on successful add, not on error.
- Loading state: button shows `Loader2` spinner + "Adding...", disabled; input also disabled.

### DomainAllowlistSection
- Rendered as a separate `<Card>` below the "Approved Emails" card on the allowlist page.
- Empty state: centered layout with `Globe` icon in `bg-primary/10` circle, heading, body, inline `AddDomainDialog` trigger.
- Populated state: `Table` with columns: Domain | Added | (actions). No search bar (domain lists are small; omit for phase 17).
- Each row:
  - Domain cell: `Globe h-4 w-4 text-muted-foreground` + `@{entry.domain}` (`font-medium`) + `<Badge variant="secondary">Domain</Badge>`
  - Added cell: `formatDate(entry.createdAt)`
  - Actions cell: `DropdownMenu` with single "Remove" item (`Trash2` icon, `text-destructive`) — calls `window.confirm()` then DELETE endpoint
- Delete flow: optimistic disable of trigger (`disabled={deleting === entry.id}`), `fetch DELETE`, success toast + `router.refresh()`, or error toast.
- Row count footer: `text-sm text-muted-foreground` — "{count} domain{s}"

### Usage Card extension
- Add a second row inside the existing usage `CardContent` below the email usage row.
- Same layout: `Globe` icon in `bg-primary/10` circle + "{count} / {limit} domains" + "{tier} plan limit".
- Progress bar only when tier limit is finite (same condition as email bar).
- "Near limit" badge (`variant="warning"`) when domain count >= 90% of tier limit.

### Allowlist page server component
- Extend `getAllowlistData` Prisma query to include `domainEntries: { orderBy: { createdAt: 'desc' } }` and `_count: { select: { entries: true, domainEntries: true } }`.
- Pass `allowlist.domainEntries` and `allowlist.id` to `<DomainAllowlistSection>`.
- Pass `allowlist._count.domainEntries` and `tierLimits.domainEntries` to usage card section.
- Add `<AddDomainDialog allowlistId={allowlist.id} />` to header action row (rightmost button after AddEmailDialog, or between AddEmailDialog and CSV buttons — keep consistent left-to-right: CSV Import | CSV Export | Add Email | Add Domain).

## Accessibility Notes

- `Dialog` from Radix UI provides focus trap, `aria-modal`, keyboard dismiss (Escape) — no manual handling needed.
- Domain input: `htmlFor`/`id` pair required between `<Label>` and `<Input>`.
- Scope warning: use `role="note"` or plain `<div>` — do not use `role="alert"` (not an error).
- Delete DropdownMenuItem: `<DropdownMenuItem className="text-destructive">` — color alone is insufficient; "Remove" label provides textual confirmation of destructive intent.
- `Loader2 animate-spin`: aria-hidden on icon; button text changes to "Adding..." for screen readers.
